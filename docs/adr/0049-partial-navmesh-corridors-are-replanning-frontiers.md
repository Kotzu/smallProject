# ADR 0049: Partial navmesh corridors are replanning frontiers

## Status

Accepted

## Context

A semantic destination may be farther than one connected Detour query can prove. Rejecting a partial result forces reviewed intermediate goals, which risks turning destination knowledge into a hardcoded route.

## Decision

The native client-asset query returns both the requested destination and the farthest proven reachable frontier. A partial corridor is executable only to that frontier. On arrival, Movement Engine observes pose again and replans toward the unchanged semantic destination.

The frontier is generated by Detour from loaded geometry. It is not stored as route knowledge. A bounded repeated-frontier gate stops progress when replanning produces the same frontier.

Static WMO/M2/doodad collision remains primarily represented by the geometry layer or a geometry-backed local obstacle query. A bounded, expiring client-observed blocker may supplement a collision missed by that layer only after physical contact and a successful alternate Detour corridor. It is not route knowledge and grants no execution authority; the lifecycle is specified in [ADR 0031](0031-client-observed-obstacle-memory.md).

## Consequences

- Long travel no longer requires operator-authored intermediate route points.
- The system distinguishes destination knowledge from transient planning frontiers.
- Partial topology and local collision failures remain separately diagnosable.
- Full live travel to Brill, Deathknell, the south-road holdout, and the corresponding returns is verified; new maps and obstacle classes remain separate evidence obligations.
